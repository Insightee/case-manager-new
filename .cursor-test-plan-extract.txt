Finance & Billing ΓÇö Test Plan
For the tech / QA team ┬╖ Test against seeded data, adversarially ┬╖ Nothing here moves real money (gateways mocked)
Purpose & how to test
This is a money module. The bugs that matter are silent ΓÇö a wrong number that looks plausible, a payout to the wrong person, a family shown the wrong bill. Happy-path clicking will not find them. The tests below are built to disagree with the system on realistic data.
Test on the seeded fixture, not an empty demo. The IC-WK case fixture is the standard ΓÇö it contains the edge conditions (mismatches, held disputes, package drawdown, transition months). Every bug you find should become a new case in that fixture so it stays caught.
Environment: test/local only, never the production (Railway) database. All external gateways (Zoho, Razorpay) are MOCKED and flag-gated ΓÇö do not test live integration here (see Out of Scope).
Priority: P1 = money-correctness or data-exposure (a wrong balance, a wrong payout, a leak). P2 = important but lower blast radius. Fix and re-test P1 before P2.

Reporting defects
For each defect, report:
Money impact first ΓÇö a wrong balance or wrong payout outranks any cosmetic issue. Rank by rupees at risk, not by how visible it is.
The exact seed condition to reproduce (which IC-WK case, or the constructed data), so a fix can be tested against the same case.
Expected vs actual numbers ΓÇö the actual value seen, not ΓÇ£looks wrong.ΓÇ¥
Empty vs broken ΓÇö distinguish ΓÇ£shows nothing because nothing was seededΓÇ¥ (not a bug) from ΓÇ£shows nothing despite seeded dataΓÇ¥ (a bug).
Out of scope for this round
Do not test or report these as broken ΓÇö they are deliberately not done yet:
Live Zoho / Razorpay ΓÇö both are mocked behind flags. A mocked ΓÇ£paidΓÇ¥ is not a real payment. Live wiring is a later, separate step.
Transition payout amounts, notice-period pay, reassignment margin thresholds ΓÇö parked pending business sign-off on the rates. The transition recording structure may exist, but the money amounts are not final.
Mobile layout & final visual design ΓÇö hardening passes not yet done; admin finance screens are desktop-first by design.
Full security review of non-payout surfaces ΓÇö only the payout path has been security-reviewed so far.
The goal of this round: find the money-logic bugs on mocked gateways, before live integration. Those are the ones cheapest to fix now and most expensive to find after cutover.
